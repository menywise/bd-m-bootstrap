Terminologie — Communiquer avec l'IA

Fichiers autoritatifs
NOYAU_VERITE
Document source de vérité absolu. Charger EN PREMIER à chaque session. Toute règle doit y être inscrite.
JOURNAL_DECISIONS
Append-only. Toute décision de session → une entrée ici. Ne jamais modifier une ligne existante.
HOW_TO_SESSION
Protocole d'ouverture/clôture de session. Étapes 0→3 obligatoires.
CTX_[MODULE]
Contexte local d'un module. 8 blocs : RÔLE / PORTÉE / AUTORISÉ / INTERDIT / DÉPENDANCES / PREMIUM / RÈGLES / HISTORIQUE.
CHANTIER_ADMIN
Plan de chantier de l'upgrade admin. Reprendre ici en cas d'amnésie conversationnelle.
Concepts projet
Périmètre actuel
Ortho-Neuro, salles 05-08, lun-ven. Hors périmètre ≠ n'existe pas.
SLOT
{salle + jour + créneau} — unité indivisible du Planning Engine. ≠ intervention chirurgicale.
window.bdbUser
Fourni par bdb-shell.js. Contient id, email, prenom, nom, initials, avatar_url, role, isAdmin.
approved
profiles_directory.approved — PAS user_roles. Anti-régression E9.
Vn / Vn+1
Vn = états calculés automatiquement. Vn+1 = états expert manuels (futur).
ARCHIVE_GEL
Contenu gelé — lecture bornée uniquement. Jamais réactiver sans validation.

Protocole session IA

Ouverture (obligatoire)
0
Déclarer le scope — MODULE EN COURS · OBJECTIF · FICHIERS IN SCOPE · HORS SCOPE · DURÉE
1
Charger NOYAU_VERITE — L'IA doit citer 3 règles critiques retenues. Sinon : relancer.
2
Charger CTX local — S'il n'existe pas, l'IA le crée depuis TEMPLATE_CTX_MODULE et tu valides.
3
Déclarer les fichiers in scope — Tout fichier non listé = hors scope = non touchable.
Clôture (obligatoire)
A
Lister les décisions prises → append dans JOURNAL_DECISIONS
B
Identifier ce qui remonte dans NOYAU → versionnement obligatoire + accord Manu
C
Mettre à jour CTX local si les règles du module ont évolué
!
Aucune règle de session ne survit — Ce qui n'est pas écrit dans un fichier est perdu.

Rappels critiques

Ne jamais faire
  • Supprimer un fichier sans validation Manu
  • Valider une règle en conversation (l'écrire dans un fichier)
  • CSS inline style="" statique dans les HTML
  • onclick="" dans les boutons — addEventListener uniquement
  • @latest sur les CDN BDB en prod — tag fixe obligatoire
  • Confondre CDS (framework) et BDB (application)
  • psql docker sans -e PGCLIENTENCODING=UTF8
  • 2 fichiers CSS pour un même module
  • Commandes Mac/Linux — Windows uniquement
  • Dupliquer le bloc auth — bdb-shell.js gère tout
  • Qualifier un module embryonnaire d'"orphelin" ou d'"erreur"
Bonnes pratiques
  • Phrase courte en début de session pour chaque IA
  • Une session = un module = un objectif clair
  • Chaque décision → JOURNAL_DECISIONS immédiatement
  • Nouveau module → partir de TEMPLATE_MODULE_BDB (3 fichiers)
  • Hiérarchie de preuve : fichier > conversation > mémoire
  • Salle canonique : normalizeSalle(v) → "05"
  • Bootstrap Icons uniquement (pas Font Awesome)
  • Recettage admin-test.html avant toute livraison
