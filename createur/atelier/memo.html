Rappels critiques

Ne jamais faire
  • Supprimer un fichier sans validation Manu
  • CSS inline style statique dans les HTML
  • Attribut onclick dans les boutons — addEventListener uniquement
  • @latest sur les CDN en prod — tag fixe obligatoire
  • Dupliquer le bloc auth — bdb-shell.js gère tout
  • Inventer un schéma DB ou une colonne sans vérification
  • UPDATE protocole_operatoire si protocole_id mappé (ERREUR-13)
  • Exécuter du SQL sans fichier .sql local (INTERDIT-SQL-01)
  • Commandes Mac/Linux — Windows uniquement
  • psql docker sans -e PGCLIENTENCODING=UTF8
Bonnes pratiques
  • session-ia.html pour ouvrir et clôturer chaque session Claude
  • Une session = un module = un objectif clair
  • Nouveau module → partir de TEMPLATE_MODULE_BDB (3 fichiers)
  • Hiérarchie de preuve : fichier > conversation > mémoire
  • Bootstrap Icons uniquement (pas Font Awesome)
  • Recettage diagnostic.html avant toute livraison
  • GFC-01 : vérifier le terrain (SELECT) avant toute migration
  • Skill atelier-session-bdb en début et fin de session

SQL / Supabase
Terme / Commande Définition
RLS (Row Level Security)Politique de sécurité Supabase : chaque ligne de table a des règles d'accès par rôle. Si la policy bloque, la requête retourne 200 OK avec 0 résultat (silencieux).
RPCRemote Procedure Call — fonction SQL exécutée côté serveur via window.bdb.rpc('nom_fonction', params).
SECURITY DEFINERClause d'une fonction SQL qui l'exécute avec les droits du créateur (contourne RLS). Utilisé pour les agrégats admin.
FK (Foreign Key)Clé étrangère — référence vers l'id d'une autre table. Garantit l'intégrité référentielle.
Table pivotTable de liaison N:N. Contient 2 FK (ex : anatomie_id + protocole_id). Aucune donnée propre.
ON CONFLICTClause SQL pour gérer les doublons sur INSERT. Ex : ON CONFLICT (anatomie_id, protocole_id) DO NOTHING.
UPSERTINSERT + UPDATE combinés. Insère si absent, met à jour si présent. Méthode Supabase : .upsert().
CASCADEComportement FK : si l'entité parent est supprimée, les enfants sont supprimés automatiquement.
JOINCroisement de deux tables sur une colonne commune. Ex : anatomie JOIN thesaurus_protocoles via bdb_liaisons.
information_schemaSchéma PostgreSQL qui décrit la structure de toutes les tables. SELECT * FROM information_schema.columns WHERE table_name='anatomie'.
.select() obligatoireToujours chaîner .select() sur .update() et .delete() Supabase — sinon RLS bloque silencieusement.
INTERDIT-SQL-01Règle BDB : tout SQL cloud doit être sauvegardé localement dans migrations/ AVANT exécution.
Migration N°xxxFichier SQL versionné dans migrations/. Numéroté séquentiellement. Jamais modifié après exécution.
UUIDIdentifiant unique universel (format xxxxxxxx-xxxx-xxxx-xxxx-xxxxxxxxxxxx). Clé primaire de toutes les tables BDB.

Architecture BDB
Terme Définition
L1 / L2 / L33 couches produit. L1 = universel (tous établissements). L2 = instance spécifique. L3 = atelier Manu×Claude (ne ship jamais).
CDS (Consensus Design System)Framework UI/technique BDB. Règles CSS, JS, chaîne de chargement. Distinct de BDB l'application.
bdb-shell.jsScript universel : auth + navigation + header. Obligatoire sur tous les modules. Injecte window.bdbUser.
window.bdbClient Supabase unique. Défini dans supabase-client.js. INTERDIT de dupliquer.
window.bdbUserObjet utilisateur courant : { id, email, prenom, role, isAdmin }. Fourni par bdb-shell.js.
bdb-invite-guard.jsIntercepte toutes les mutations Supabase si role='invite'. Doit être chargé AVANT bdb-shell.js.
Chaîne JSOrdre obligatoire : supabase-client.js → bdb-invite-guard.js → bdb-shell.js → [module].js
INTERDIT-ExxRègle d'architecture numérotée dans CHANTIER_TECHNIQUE. Ex : INTERDIT-E1 = #bdb-shell premier enfant de main.
Module embryonnaireModule existant en dossier, contenu vide ou partiel. Ne pas supprimer sans accord Manu.
atelier_decisionsTable Supabase L3 — log permanent de toutes les décisions architecturales. 313+ entrées.
atelier_sessionsTable Supabase L3 — sessions de travail numérotées. Source de vérité du backlog.
Source de véritéDocument ou table qui prime en cas de conflit. Hiérarchie : MANIFESTE → JOURNAL_DECISIONS → CTX_ARCHITECTURE → CTX_MODULE.
PersonaProfil utilisateur typé (Julie novice, Olivia cadre, Le Chirurgien chirurgien…). Guide les décisions UX.
