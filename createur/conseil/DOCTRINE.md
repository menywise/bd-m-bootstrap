# DOCTRINE — Conseil BDB

## Pourquoi le conseil existe

BDB produit du code, des décisions, des architectures.
Claude commet des erreurs par automatisme, confort ou manque de contradiction.
Le conseil existe pour simuler les voix qui cassent ce qu'on a mal construit
— avant que le terrain le fasse à nos dépens.

## Ce que le conseil n'est pas

- Pas un bloquant administratif
- Pas une validation hiérarchique
- Pas un comité de censure

Ce qu'il est : un instrument de diagnostic à 5 voix divergentes
qui brisent ce qui est fragile — avant le terrain.

## Anti-collision

Toute soumission déclare ses zones de collision :

- Tables DB touchées
- Modules JS impactés
- Sessions parallèles connues
- Risque : si X s'exécute pendant que Y tourne

## Principe fondateur

> Un livrable qui traverse les 5 lunettes sans fragilité P1
> est un livrable qu'on peut exécuter les yeux fermés.
> Un livrable qui n'a pas traversé les 5 lunettes
> est un livrable qu'on exécute en espérant.
