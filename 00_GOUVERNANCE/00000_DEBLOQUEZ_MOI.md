### Type 8 — Protection

## Les 4 couches de DB&M

DB&M fonctionne en 4 couches. Chaque couche a ses acteurs,
ses promesses, et son niveau de visibilité.

**La fondation** — ce qui ne change jamais.
Les documents fondateurs. Les principes en base.
Les interdits. Les templates conformes.
Invisible pour les utilisateurs. Vital pour tout le reste.
Personne ne touche à cette couche sans accord explicite.

**Le produit universel** — ce que chaque IBODE voit et utilise,
quel que soit l'établissement.
Les modules, les fiches, le glossaire, le thésaurus.
Le wording empathique. La chaîne connectée :
thésaurus → fiches → matériel → arsenal →
préférences chirurgien → installation → glossaire → anatomie.
Si un maillon manque, la chaîne ne vaut rien.

**L'instance** — ce qui est spécifique à un établissement.
Les chirurgiens avec leurs vrais noms. Le matériel avec
ses vrais noms tels qu'ils existent dans le logiciel de l'hôpital.
Les emplacements réels dans l'arsenal.
C'est ce qui fait que DB&M n'est pas un wiki générique
mais l'outil de TON bloc.

**L'espace créateur** — ce qui pilote tout le reste.
L'atelier de travail. Le conseil. Les sessions. Les décisions.
Le cockpit. Les audits. Les skills. Les prompts.
Visible uniquement par Manu et les IA qui travaillent
sur le projet.

## Méthode MERE — comment tout s'apprend ici

Chaque concept dans DB&M s'enseigne avec cette méthode :

**Motivation** — pourquoi tu as besoin de comprendre ça.
Sans le pourquoi, l'adulte n'apprend pas.

**Explication** — ce que c'est, en clair, avec un exemple
ancré dans la réalité du bloc opératoire.

**Recette** — comment le faire concrètement. Les étapes.

**Exercice** — le mettre en pratique sur un cas réel.
C'est là que la compréhension passe du mental à l'action.

Tu viens d'utiliser MERE sans le savoir en lisant ce document.

L'explication : la spirale, l'ennéagramme, le DISC, le logo.
La recette : lire les fondateurs, appeler la reprise, vérifier.

MERE s'applique à MERE. C'est fractal.
